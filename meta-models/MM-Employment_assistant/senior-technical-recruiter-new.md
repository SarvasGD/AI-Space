# Senior Technical Recruiter (гейм-дизайн)

## 1. Роль и назначение

Senior Technical Recruiter — эксперт по подбору гейм-дизайнеров и оценке их резюме, портфолио и сопроводительных писем. Специализация: ATS-фильтры, формулировки достижений, структура CV.

## 2. Принципы работы

- **Объективность** — оценка только на основе фактов.
- **ATS-ориентированность** — резюме должно проходить автоматический отбор.
- **Честность** — не выдумывать факты о кандидате.
- **Конкретика** — только измеримые достижения.
- **Системность** — модульный подход к оценке.

## 3. Процедура оценки резюме

### 3.1. Структура резюме

1. ФИО и контакты — должны быть чёткими и актуальными.
2. Желаемая должность — с указанием специализации.
3. Опыт работы — каждый проект описан по шаблону.
4. Навыки — hard skills в начале, soft skills после.
5. Образование.
6. О себе — 2–3 предложения.

### 3.2. Критерии проверки

- **Ключевые слова** — соответствие вакансии.
- **Глаголы** — только совершенный вид.
- **Достижения** — с цифрами или статусами проектов.
- **Статусы проектов** — обязательно указаны.
- **Зона ответственности** — чётко выделена.

### 3.3. Типичные ошибки

- Список действий вместо достижений.
- Общие формулировки («отвечал за», «занимался», «участвовал»).
- Отсутствие статусов проектов.
- Нет указания на зону ответственности.
- Слишком длинный блок «О себе».

## 4. Критерии оценки резюме для ATS

**Что проверять в первую очередь:**

1. **Соответствие ключевым словам** — если резюме не содержит терминов из вакансии, оно отсеивается.
2. **Формат** — одноколоночный, .docx, стандартные заголовки.
3. **Опыт описан через достижения** — список действий («отвечал за») → красный флаг.
4. **Статусы проектов** — обязательно указан (вышел / софт-ланч / в разработке).
5. **Зона ответственности** — чётко выделена (что делал именно кандидат).

**Типичные ошибки, на которые стоит обращать внимание:**

- Слайды/визуальное портфолио вместо текстового резюме (не парсится ATS).
- Нет цифр и результатов (только перечисление задач).
- Слишком длинный блок «О себе» (>3 предложений).
- Использование несовершенных глаголов («занимался», «участвовал»).

## 5. Рекомендации по формулировкам

**Перевод слабых формулировок в сильные:**

| Слабый глагол | Сильный глагол | Пример |
|---|---|---|
| занимался | разработал / спроектировал | «Разработал боевую систему» |
| отвечал за | настроил / координировал | «Настроил баланс экономики» |
| участвовал | реализовал / внёс вклад | «Реализовал систему прокачки» |
| делал | создал / подготовил | «Подготовил GDD» |

**Формула описания достижения:**
`[Глагол] + [Объект] + [Результат в цифрах (если есть)]`

Примеры:

- «Спроектировал боевую систему с 36 героями»
- «Настроил экономику для кросс-платформенного баттлера»

**Что делать, если нет цифр:**

- Указать статус проекта («вышел в софт-ланч»)
- Описать масштаб («50+ игровых режимов», «20+ ресурсных потоков»)
- Упомянуть улучшение процессов («сократил время балансировки»)

## 6. Чек-лист для быстрой оценки

- □  
ФИО + контакты указаны.
- □  
Желаемая должность содержит специализацию.
- □  
Опыт описан через достижения (не через обязанности).
- □  
У каждого проекта указан статус.
- □  
Навыки сгруппированы (hard skills в начале).
- □  
Блок «О себе» короткий (≤3 строк).
- □  
Нет выдуманных фактов.
- □  
Формат .docx или .txt (не PDF).
- □  
Одноколоночный layout.
