## 0. Workflow
Контент сначала в чате → явное **«ок, финал»** → правка `content.md` / `index.html`. Без апрува файлы не трогать.

---

## 1. Структура таблицы
Столбцы (порядок фиксирован): **Проект → Продакт-менеджмент → Игровые системы → Мета-игра → Баланс → UX/UI-Дизайн → Результат**.  
«Мета-игра» — окончательное название. Строки — все проекты из секции «Проекты» `content.md` (15 проектов).

---

## 2. Формула расчёта процента для категории
```
% = (Σ выполнения по каждой стандартной подзадаче) / (кол-во запланированных подзадач × 100%) × 100
```
Подзадача может быть выполнена частично. Количество подзадач берётся из источников или стандартного списка (4 на категорию).

---

## 3. Стандартные подзадачи по категориям
| Категория | Подзадачи |
|-----------|-----------|
| Продакт-менеджмент | 1. Видение и позиционирование · 2. Анализ рынка и референсов · 3. Roadmap · 4. Проектная документация (GDD/ТЗ) |
| Игровые системы | 1. Core-геймплей · 2. Системы прогрессии/прокачки · 3. Системная архитектура · 4. Экономические/сквозные механики |
| Мета-игра | 1. Игровой/мета-цикл · 2. Игровые режимы · 3. Механики удержания (дейлики, квесты) · 4. Система коллекционирования/анлоков |
| Баланс | 1. Матмодель баланса · 2. Источники и стоки ресурсов · 3. Монетизационные точки · 4. Боевой баланс (кривые, TTK) |
| UX/UI-Дизайн | 1. User Flows · 2. Wireframes/прототипы · 3. UX-логика · 4. Финальная UI-разметка |

---

## 4. Формула итогового столбца «Результат»
```
Результат% = round( (Σ процентов 5 категорий) / 5 )
```
Прочерк считается как 0, если все 5 — прочерк, то результат без числа.

---

## 5. Прочерки — два типа
- **(A) Структурное исключение** — категория не участвует в расчёте (исключается из знаменателя). Примеры: Encased → Продакт-менеджмент, Мета-игра; Iron Frontier → Продакт-менеджмент, UX/UI, Мета-игра; Отзвуки → Мета-игра; Chaffer → Мета-игра, Игровые системы, Баланс.
- **(B) Применимо, но не выполнялось** — категория участвует как 0%. Примеры: Enchained → Мета-игра; Space Troopers TD → все незаполненные.

## 8–9. Формат ячейки (с декомпозицией по частям речи)

### 8. Формат ячейки категории (все 5 столбцов)
```
NN%<br>
Артефакт: [ссылка-чип] (если есть, максимум одна)
(пустая строка)
[Глагол(ы)] + [Сущность (=заголовок)]:
• [Однородное существительное в Им.п.]
• [Однородное существительное в Им.п.]
• ...
```

#### Декомпозиция по частям речи:
| Компонент | Часть речи | Пример (эталон: Трон Мидгарда, Игровые системы) | Пример (правильный: Encased, Игровые системы) |
|-----------|------------|------------------------------------------------|------------------------------------------------|
| **Компакт** | Глагол (ед.ч., сов.вид) + Существительное (мн.ч., Им.п.) | «Разработал игровые системы» | «Выявил проблемы и структурировал игровые системы» |
| **Подпункты** | Однородные существительные (Им.п.) | «Характеристики, Архетипизация, Скиллы, Прокачка и мощь, Обмен, Бой» | «Лутинг, Торговля, Прокачка и мощь, Боёвки» |

**Правила:**
- Компакт — это первая строка под процентом и артефактом. Он всегда строится по схеме: **Глагол(ы) + Сущность**.
- Подпункты — это всегда **однородные существительные в именительном падеже** (или в том падеже, который диктует сущность), перечисляющие конкретные системы/задачи.
- Глагол выбирается под характер работы:
  - **Создание с нуля / разработка:** разработал, спроектировал, создал, построил, реализовал.
  - **Анализ / исследование:** выявил, обнаружил, проанализировал, структурировал, систематизировал.
  - **Доработка / улучшение:** доработал, переработал, настроил, скорректировал, оптимизировал.
- Подпункты перечисляются через двоеточие после компакта, через маркеры «•», каждый подпункт — это отдельная сущность, а не целое предложение.

---

### 9. Формат ячейки «Результат»
```
NN%<br>
[Глагол(ы)] + [Сущность (главный итог)]:
• [Однородное существительное в Им.п. / Предл.п.]
• [Однородное существительное в Им.п. / Предл.п.]
• ...
```

#### Декомпозиция по частям речи:
| Компонент | Часть речи | Пример (эталон: Трон Мидгарда, Результат) | Пример (правильный: Encased, Результат) |
|-----------|------------|-------------------------------------------|------------------------------------------|
| **Компакт** | Глагол (ед.ч., сов.вид) + Глагол (ед.ч., сов.вид) + Существительное (Вин.п.) | «Модернизировал вижн и разработал геймдизайн MVP» | «Сделал анализ Encased, обнаружил и предложил решения проблем в» |
| **Подпункты** | Однородные существительные (Им.п. или Предл.п.) | «36 героев и 6 боссов, 150+ скиллов, 5 игровых режимов и дэйликов, 20+ ресурсов, софт-ланч» | «Балансе, Игровых системах, UX/UI-дизайне» |

**Правила:**
- Компакт — жирным шрифтом, строится по схеме: **Глагол(ы) + Сущность**.
- Подпункты перечисляют ключевые результаты или направления. Они могут быть в именительном падеже (если перечисляются созданные объекты) или в предложном падеже (если перечисляются области, в которых были решения).
- Результат не должен дублировать формулировки категорий дословно, но должен синтезировать их в ёмкий вывод.

---

## 10. Правила текста (дополнено)
- Каждый пункт должен нести новый факт, не дублироваться, быть полезным.
- Глаголы уникальны в пределах всей строки (все 5 категорий + результат).
- Порядок пунктов — по логике разработки (core-геймплей первым в «Игровые системы»).
- Честность про роль: если делегировано — писать «поставил ТЗ», «согласовал».
- Не изобретать факты.
- **Глагол должен точно отражать тип работы:** создание, анализ, доработка.
- **Если пользователь дал готовую формулировку — она становится эталоном. Её нужно копировать, а не переформулировать.**

## 12. Алгоритм сборки строки (с новым принципом)

### 12.0. Основной принцип: «Беру эталонную форму и адаптирую под проект»
1. Взять эталонную строку (Трон Мидгарда или Stellar Wind Idle) как образец **грамматической формы**.
2. Извлечь из неё структуру: глагол + сущность + подпункты (однородные существительные).
3. Определить характер работы по проекту (создание, анализ, доработка) на основе источников.
4. Подобрать глаголы, соответствующие характеру работы, но сохранить форму.
5. Наполнить сущность и подпункты конкретными данными из источников по проекту.
6. Сохранить структуру подпунктов как список однородных существительных.

### 12.1. Пошаговый алгоритм
1. Собрать пункты из всех источников.
2. Реклассифицировать по смыслу.
3. Определить применимость категорий.
4. Посчитать % по формуле.
5. Найти артефакты.
6. **Определить характер работы (создание, анализ, доработка) и подобрать глаголы.**
7. **Собрать компакт по шаблону: глагол + сущность.**
8. **Собрать подпункты как список однородных существительных (без глаголов).**
9. Проверить тест на каждый пункт.
10. Проверить уникальность глаголов в строке.
11. Проверить, что пользовательские правки, если они были, применены и не переформулированы.
12. Посчитать результат.
13. Показать в чате читаемую таблицу.
14. После апрува — вносить в файлы.
